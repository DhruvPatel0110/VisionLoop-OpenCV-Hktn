================================================================================
MANDATORY ARCHITECTURAL & METHODOLOGICAL PRINCIPLES
================================================================================
1. Grounded Quality Evaluation:
   - Comparing a candidate to the baseline does NOT prove correctness.
   - Use reference/ground-truth edge maps for benchmark images (e.g., BSDS500 or
     verified reference edges) and measure Precision, Recall, and F1-score.
   - For unlabelled images, clearly label edge density and noise penalties as
     "proxy metrics" rather than proof of correctness.
   - Never accept a faster configuration that degrades output quality below Q_min.

2. Explicit OpenCV 5 Verification:
   - Do NOT assume standard `pip install opencv-python` installs OpenCV 5.
   - Explicitly verify `cv2.__version__` starts with 5.x and required APIs run.
   - If OpenCV 5 pre-release wheels/builds are missing, resolve this immediately 
     before writing any agent or UI code.

3. Single Focused AWS Architecture:
   - Do not divide effort across multiple AWS compute options.
   - Target ONE architecture: AWS Lambda with Container Image (or single lightweight
     container on ECS/App Runner). Evaluate Lambda container first for bounded,
     stateless CPU vision jobs.
   - Enforce hard cost safeguards: payload caps (<1MB), 15s execution timeouts,
     CloudWatch billing alarms, and immediate teardown of unused resources.

4. Genuine Perception-Action Feedback:
   - The agent MUST NOT execute a fixed, predetermined parameter list.
   - Visual output metrics (e.g., lost edges, excessive noise) and execution time
     must dynamically alter the subsequent candidate configuration and logged rationale.

5. Realistic Scoping:
   - Phase 5 (RAG, A2A, MCP, COOL) is strictly optional. A working core project with
     reproducible evidence is far superior to an unfinished multi-protocol system.

PHASE 1: WORKLOAD DEFINITION & GROUNDED EVALUATION HARNESS (Priority 1)
--------------------------------------------------------------------------------
Objective: Implement the CPU-friendly vision workload (Edge Detection), curate a
           ground-truth reference test set, and build a rigorous evaluation harness.

Tasks:
  1.1 Workload Implementation (Edge Detection):
      - Implement modular edge detection pipeline in src/vision/edge_detector.py.
      - Parameter space with bounded values:
        * Low threshold (e.g., 20 - 150)
        * High threshold (e.g., 100 - 300)
        * Aperture/Kernel size (3, 5, 7)
        * L2gradient (True / False)
        * Pre-processing smoothing (Gaussian blur kernel / sigma)
  1.2 Ground-Truth Test Dataset Curation:
      - Assemble 4-6 diverse, small static test images (max 800x800):
        * High contrast / sharp object boundaries
        * Low contrast / poor illumination
        * Textured / noisy background
      - Provide verified reference edge maps for benchmark images (e.g., from
        standard datasets like BSDS500 or curated expert-labeled edges).
  1.3 Grounded Quality Evaluation Engine:
      - For images with reference edge maps:
        * Calculate Edge Precision, Recall, and F1-score against reference.
      - For unlabelled images:
        * Calculate explicit proxy metrics (edge continuity, edge pixel density,
          high-frequency noise penalty).
        * Explicitly tag proxy scores in logs as "proxy indicators", NOT ground truth.
      - Do NOT treat SSIM against an arbitrary baseline as proof of correctness.
  1.4 Runtime Measurement & Noise Reduction:
      - High-resolution timing using time.perf_counter_ns().
      - Run 3 warmup iterations and take median of 5 timed runs to eliminate CPU jitter.
  1.5 Quality Guardrail Enforcement:
      - Define minimum quality threshold (e.g., F1 >= 0.75 or Proxy_Q >= 0.70).
      - Strict rule: Candidates failing quality criteria are rejected regardless
        of how fast they run.
  1.6 Robust Error & Boundary Handling:
      - Handle corrupted files, unsupported dimensions, zero-edge edge maps, and
        parameter out-of-bound errors gracefully.

Exit Criteria / Deliverables:
  [x] Parameterized OpenCV 5 edge detection module (src/vision/edge_detector.py).
  [x] Grounded evaluator (src/eval/evaluator.py) calculating F1 / proxy scores.
  [x] Curated dataset with reference edge maps in data/ (5 benchmark images + manifest).
  [x] Documented baseline metrics recorded for all benchmark images (data/baseline_results.json).

PHASE 2: AUTONOMOUS AGENT LOOP & ADAPTIVE DECISION ENGINE (Priority 2)
--------------------------------------------------------------------------------
Objective: Implement the autonomous coordinator where measured visual outputs and
           runtimes directly drive the agent's next action and parameter choice.

Tasks:
  2.1 Agent State Machine & Budget Constraints:
      - State flow: BASELINE -> PROPOSE -> EXECUTE -> EVALUATE -> DECIDE -> NEXT/STOP.
      - Hard budget cap: Max 5-8 candidate experiments or 30-second total runtime.
  2.2 Adaptive Feedback-Driven Search (Perception -> Decision -> Action):
      - Replace fixed parameter sweeps with genuine adaptive heuristics:
        * If candidate was faster but F1/quality failed (too many lost edges):
          Agent records "over-suppression detected", lowers high threshold, or
          reduces blur kernel in the next candidate.
        * If candidate has excess noise (precision drops):
          Agent records "noise artifacts detected", increases low threshold or
          adds pre-smoothing.
        * If candidate is slower without quality gain:
          Agent abandons current parameter branch and explores alternative kernel.
        * If candidate is faster and meets quality threshold:
          Agent accepts candidate as new best, and attempts fine-tuning.
  2.3 Audit Trail & Trace Logging:
      - Record structured step-by-step experiment log:
        * Iteration index, timestamp, tested parameters
        * Measured runtime and speedup factor vs. baseline
        * Quality score (F1 / proxy metric) and pass/fail status
        * Explicit decision reasoning (e.g., "Rejected: 22% faster but lost 40% of 
          fine edges; adapting low_threshold from 80 down to 50 for next run")
        * Next selected action
      - Export full audit trace to JSON (runs/trace_{timestamp}.json).
  2.4 Stop Conditions & Winner Selection:
      - Terminate when budget is exhausted, convergence is achieved, or target
        latency reduction is reached without quality loss.
      - Output best validated configuration and clear failure analysis.

Exit Criteria / Deliverables:
  [x] Adaptive loop coordinator (src/agent/coordinator.py, src/agent/optimizer.py).
  [x] Verified execution trace proving visual results alter the subsequent test (demonstrated on low-contrast & noisy benchmarks).
  [x] Trace export to structured JSON with explicit rationale for every decision (runs/*/experiment_trace.json & experiment_report.md).

           mandatory competition requirement with verifiable execution and cost limits.

Tasks:
  3.1 Selected Architecture: AWS Lambda Container Image:
      - Focused selection: AWS Lambda with container packaging (x86_64 or Graviton).
      - Rationale: Fully managed, serverless, zero idle cost, bounded execution time,
        and suitable for discrete, single-image CPU workloads.
      - (Fallback only if Lambda payload/memory constraints fail: small AWS App
        Runner or ECS service).
  3.2 Containerization (Dockerfile):
      - Create optimized Dockerfile based on official AWS Lambda Python runtime.
      - Install verified OpenCV 5 dependencies and libraries.
      - Expose handler accepting: { image_bytes_base64, task, parameters }.
      - Returns: { output_image_base64, server_execution_time_ms, host_info }.
      - Verify container builds and runs locally with AWS Lambda RIE before deploying.
  3.3 Deployment & Verification:
      - Deploy container image to Amazon ECR.
      - Create Lambda function with Lambda Function URL (or API Gateway) with auth.
      - Configure function limits: 1024MB RAM, 15-second execution timeout.
  3.4 Local Client Integration:
      - Implement client bridge (src/aws/cloud_executor.py) allowing the agent loop
        to route workload execution to either Local CPU or AWS Cloud.
      - Implement retry with backoff and graceful error recovery on network drops.
  3.5 Spending Limits & Cost Safeguards:
      - Set AWS Billing Budgets and CloudWatch alarm at $5.00 threshold.
      - Restrict incoming image payload to < 1 MB.
      - Write automated teardown script (scripts/teardown_aws.sh) to clean up
        ECR images and Lambda function immediately after testing.
